# WL-04｜原生批注底稿

两条流程共用编号。两套原型已可操作，以下是给内置浏览器原生批注用的底稿和定位；当前未写入原生标点。

| 编号 | 演示入口 | 元素 ID |
|---|---|---|
| 01–02 | [工单详情](../prototype/ticket/index.html#ticket-detail) | `ticket-desk-entry`、`ticket-customer-info` |
| 03 | [工单表格](../prototype/ticket/index.html?view=table#ticket-list) | `ticket-export` |
| 04 | [工单详情](../prototype/ticket/index.html#ticket-detail) | `ticket-customer-info`、`ticket-scope` |
| 05–06 | [开放平台工单域](../prototype/open-platform/index.html?focus=pii#open-app) | `pii-option`、`pii-status-anchor` |
| 07 | [工单接口响应示例](../prototype/open-platform/index.html#open-doc) | `response-example` |

| 编号 | 页面 / 锚点 | 原生批注内容 |
|---|---|---|
| 01 | 工单入口「工单」 | **01 总说明。01.1 功能交互**：有权查看该工单的客服默认看到遮盖值，点眼睛看原文，再点收起；开放平台按应用申请，见 05–07。**01.2 影响范围**：工单列表和详情里的客户姓名、邮箱、电话；同一结构化字段在回复及信头中的显示；导出及撤权口径见 03–04。**01.3 本期边界**：沿用原工单角色范围，租户管理员独立配置后期，正文与附件不承诺自动识别。 |
| 02 | 工单详情「客户信息」的眼睛 / 复制 | **02 显示与复制。** 默认遮盖，点击只展开对应字段；收起、换工单、离开或刷新后恢复遮盖。遮盖时复制不得给出原文，展开后可沿用现有复制。客户端不得把切换状态变成账户或租户偏好。正常回复和拨号仍使用真实地址或号码，遮盖文本不传给发送接口。 |
| 03 | 工单表格现有「导出」入口 | **03 导出。** 现有标签/消息导出可带客户邮箱，消息导出也含沟通记录。眼睛开关不改变导出结果或权限；导出使用独立的既有工单导出权限。上线前逐项核对导出表头与下载文件，明确结构化字段是否遮盖、正文是否包含联系方式；本轮不增加导出权限配置或新入口。 |
| 04 | 工单详情「客户信息」的眼睛 | **04 工单权限撤销与留痕。** 原角色或工单范围被撤销后，后续详情与原文请求应按既有权限拒绝，并清除本页已展开状态；不能回收此前复制或下载的数据。建议原文查看记录操作者、时间、工作空间、工单和字段名，日志不写值；不新增独立审计页面。 |
| 05 | 开放平台应用「申请工单个人信息读取」 | **05 权限申请。** 创建应用、持有 Client ID/Secret 或已有工单工作域不等于可取个人信息原文。申请写清字段和用途，按应用与当前工作空间提交；只给已审批的字段，扩大范围重审。 |
| 06 | 开放平台应用「授权状态」 | **06 授权与撤销。** 审核中、未通过、撤销都不放出未授权字段原文。按当前授权即时检查，不能靠旧令牌或空 scope 继承。记录授权变化及操作者，不记录客户值；历史已交付副本无法靠撤权召回。本期不设独立租户配置或审核后台。 |
| 07 | API 文档「响应示例」 | **07 数据出口。** 列表、详情、消息按各自实际字段核对，当前工作域权限仍先判；Webhooks 及投递记录/重试也须验真实出参，不能从这些位置拿到未授权原文。正文、主题和自定义字段可能包含个人信息，按单独口径处理；示例遮盖仅说明结构化字段，不代表已实现全量识别。 |
