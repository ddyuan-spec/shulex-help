## P01 问卷配置（survey-list及三步）

来源S01/R01–R03。列表与编辑布局按A类保留，新开关放在题目卡内的用途区域，评分题靠近现有考核开关但保持两个独立控件；单/多选同位置提供分析开关，文本不提供。

### 交互

1. 新建题目及无配置的旧题默认关闭。已保存GOFO示例Q1/Q2可预置开启，须明确其是已配置示例，不改默认规则。
2. 切换开关只改草稿，客户预览内容不变，“纳入客服考核”不变。
3. 保存沿原第三步统一校验并提交；重开编辑/刷新后按稳定题ID回填开关，不能仅保留按钮状态。
4. 已保存配置被分析页读取；未保存草稿不提前进入候选条件。
5. 单/多选切为文本时该题不再可筛；不能在已有分析页静默删除已应用条件，应在重新查询时进入配置失效状态。
6. 原题目/选项/邀请内容的校验与操作保持。删除沿用真实确认流程，取消不修改数据；不为本轮新增整卷删除、复制或批量操作。

保存状态：正常、保存中、校验失败、保存失败（保留草稿）、成功回列表。存储失败不能显示“保存成功”；不在本地原型声称调用真实业务API。

## P02 满意度分析（report）

### 本轮开发确认版 v6（用户最新裁定，优先于本节旧三卡设计）

影响范围为report单页及其个人展示偏好；不新增页面跳转，不动问卷基座。用户截图是六项卡片外观/名称依据：好评率、好评数量、差评数量、发出邀评数量、已填写邀评数量、邀评链接点击率。加有效评分答卷数、NPS，共8个候选，最多显示6个；删除旧设计中的独立“9–10分占比”卡片。

新增“设置统计”就地勾选面板，复用现有下拉/复选/按钮组件；默认勾选原六项，按固定候选顺序显示；选满6项后其余选项禁用，取消一项可继续勾选。最少保留1项，支持取消和应用；应用保存本人偏好，刷新/切换渠道或问卷保留；保存失败保留原展示且草稿可重试。不增加拖拽排序、团队共享设置。

全部问卷沿用V131基座合成数据；指定问卷保留原六项与下方原报表结构，旧统计关联未确认时为—/待确认空态，不显示无关基座数值。原图表为：按日/月好评率与已填写邀评数量、按团队/渠道好评率Top10。撤下上版新增的评分分布、推荐意愿构成、9–10占比趋势。NPS与有效评分数使用已明确GOFO Q1的当前答卷样本；未选具体问卷或无有效来源时显示“—”，不跨问卷猜评分来源。

开发待确认边界：原六项/旧图表是否能接入问卷和题目答案条件、邀请与答卷关联、发送时间与提交时间、多题客服考核阈值与GOFO9–10阈值不得混算。当前原型评审栏及原统计Tooltip明确标注旧六项/图表尚未证明支持该联动，不能将基座示例当作筛选后真实结果。已提交答卷条件不能直接扩大为未回答邀请的分母；此项交刘杰估工时独立判断。

2026-11-09用户增量裁定：单页影响（report.js / report.css），不改导航与既有基座。8个候选统计，计算方式统一放在指标名称旁的圆圈感叹号中，移入展示、移出关闭；键盘聚焦可查看、Esc关闭。删除指定问卷的“计算方式”折叠块，数值、分子分母、筛选与导出逻辑不变。用户本次指令即该提示交互的设计依据。

来源S02–S04/R04–R08。直接在原满意度页面增加问卷维度，不新增并列“问卷统计”模块。上部沿现有筛选布局，问卷选择在渠道后，题目条件在下一行；下部保留卡片→图表→明细入口层级。

### 条件与结果

| 控件 | 行为 |
| --- | --- |
| 日期 | 全部问卷按原链接日期解释；指定问卷切为提交日期，标签同步变更。切换保留日期范围，不能把新提交指标放在“发送日期”下 |
| 渠道 | 沿现有单选。候选问卷来自模拟的配置/正式关联数据，不按时间内是否有答案删候选 |
| 问卷 | 单选，真实初始默认全部。历史停用且有关联的问卷可选并显示状态 |
| 题目条件 | 只生成开启题目的条件；选项/分值可多选，支持“未作答”，同题OR/跨题AND |
| 查询 | 原基础条件沿原即时联动；题目多选展开内完成后统一应用。应用前不拿草稿条件标题搭配旧结果 |
| 重置题目条件 | 只清题目答案，保留日期/渠道/问卷；沿原全局重置恢复全部条件 |

全部问卷时原有六张卡及曲线保持原义；指定问卷时结果区域切换为问卷答卷统计，明确单位为“份”。团队、处理人等既有范围字段保留，题目筛选必须在同份答卷判断，工单上的两份答卷不能拼接。

### GOFO结果与评分来源

- 预置Q1明确为0–10分推荐意愿来源；不是根据“0–10”自动识别。结果显示“评分题：Q1 推荐意愿”及对应问卷。
- 结果卡：原六项+有效评分答卷数+NPS，共8选最多6；默认原六项。旧图表结构保留，不新增评分分布。
- 整体100份、70推荐/20被动/10贬损：NPS +60，高分率70%。客服40份：28推荐/8被动/4贬损，NPS也为+60，高分率28/40=70%。此NPS相同仅是样例分布巧合，结果必须实际重算。
- 客服条件是Q2包含“客服响应与问题解决”，Q1留空；若用户主动再筛Q1=9–10，当前结果28份、NPS +100、高分率100%，条件摘要明确是高分样本，方案不得把100%解读为全体客服满意率。
- 多评分题未配置来源时不猜测来源、不显示伪NPS；展示评分来源未配置状态。通用绑定编辑交互仍为产品待评审项，本轮不擅自增加公式设置页。

## P03 答卷明细（responses）与P04详情（response-detail）

来源S03/R08。作为独立内容页，顶部返回及标题，中部条件摘要、结果数与表格，分页和导出。详情沿同一外壳显示问卷、版本、答卷ID、提交时间、工单ID和完整题目/答案；不新增客户管理、跟进、回访或消息动作。

明细列：答卷ID、问卷/版本、提交时间、渠道、工单ID、Q1评分、Q2环节、其他题目答案、查看详情。未作答显示“未作答”，0分显示0，不合并含义。多选用选项身份匹配；文字用于展示。

CSV必须真实下载，使用UTF-8，正确转义逗号/引号/换行。范围是**当前已应用条件的全部命中答卷，不受分页限制、不截断条数**，并包含条件/生成时点信息。技能通用全量规则在此按产品R08收敛，不能导出未命中的答卷冒充同集合。空结果导出禁用；失败有反馈，不能用Toast冒充下载成功。

原型新增评分卡片、分页和导出使用同一模拟集合版本；原六项和旧图表关联待确认。技术实现后的权限、快照和真实导出任务仍需联调；本地文件下载不能当后端验收。
