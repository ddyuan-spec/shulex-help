## 分期放行

- A0/A1：A01–A09、A18–A24 中相关发送/迁移/权限用例；需逐调用路径覆盖，不能只测一个控制器。
- B：A10–A13；排障轮次、邀评窗口和租户承诺批准后才可验收精确数值。
- C：A14–A17、A24；需实际负责人、公开链接验证和管理员兜底，不以静态页代替可靠派发。
- D：A22–A23及参数版本、回放与误拦复核；影子观察和正式启用分别记录。

## 业务效果观察

在明确同口径基线、时间窗口及租户/用途变化后，分别观察 SES 官方健康、内部队列投诉、正常服务误拦和待处理时长、反馈处理与回复质量。原包4周试点是候选计划，不承诺降幅；投诉减少不能仅归因于新增反馈入口，也可能来自平台代发量下降，须同时看发送量和渠道迁移。

## 邮件内投诉独立流程（R09 / F40–F45）

| 编号 | 操作 | 可观察结果 |
| --- | --- | --- |
| A25 | 对比 SES 已开启的 AURORA 和未开启的 NOVA；开关偏好保存，平台开通/限制/解除限制后再看 | SES 已开放必开且不可关闭；未开放、已限制或复核中可独立开关，无偏好默认关闭；资格变化自动重算有效状态，非 SES 偏好留存；仅平台可开通、限制、解除并留依据；不改发送偏好、不重发旧队列，已发有效链接不回收。 |
| A26 | 人工和 AI 分别用 SES、自有通道发对客服务邮件；对比独立开关打开和关闭，再测多个收件人及内部邮件 | 投诉有效开启时合格外发邮件的 HTML/纯文本自动带一次入口，无需人工插入；关闭的新邮件不带；禁止发送不外发，多个收件人无法安全校验时不加入口。 |
| A27 | 链接被扫描、顾客打开未确认、原收件人确认、转发/过期或撤销后提交 | 前两类零写入；原收件人确认成功后有投诉编号；校验不通过不建单、不泄露工单数据，不发送自动确认邮件。 |
| A28 | 重复点击确认、响应超时后查原结果，再模拟待办派发失败和重试 | 同一发送邮件和收件人只有一条投诉；查询显示原结果；待办失败不丢投诉，重试不生成新投诉或重复待办。 |
| A29 | 从租户待办、原工单和平台租户详情打开同一编号；用其他租户账号尝试打开 | 三方看到同一记录及最新状态，字段按角色授权；只有有权的租户负责人可结案，跨租户和无原工单权限的客服不能读。 |
| A30 | 租户负责人认领、处理并填写理由结案；再试本人涉诉、无负责人 | 三处依次回显待处理、处理中、已结案；本人涉诉转上级或平台复核，无人保留待分派；工单不自动重开、顾客不收到自动回复。 |
| A31 | 同一发送先收站内投诉，再收到一条可信、已归属的 AWS Complaint | 保留两种来源；站内投诉只把已验证的原收件邮箱加入本租户黑名单，复用原发送检查；结案不移出黑名单、不增加 SES 分子；AWS 回执按原有规则去重后才计入；关联不可靠时不合并。 |
| A32 | 两租户共用投诉表单；关闭其中一家投诉入口；从选择器新建并换绑；检查后台和顾客流程 | 引用期间禁止编辑和删除；仅保存租户设置才换绑；后台仅有邮件页脚示意，按开关展示按钮且不跳转；原邮件里的真实投诉入口打开对应顾客表单。 |
| A33 | 发送带必填原因表单的邮件，换绑并删除旧表单后从原信进入 | 旧信展示原版本，空白原因不能提交；之后新发的邮件用新选择。 |
邮箱原型补充验收（A02）：从「智能客服 → 集成 → 邮箱」选择对应邮箱；高级设置分别显示 SMTP 与 IMAP 的服务器、加密方式、端口，587 使用 STARTTLS。失败留在抽屉；成功仅更新选中邮箱的连接状态和验证时间。SMTP 验证不发测试信，授权成功不改变租户 SES 资格。另检查批量授权两页签和列表返回。
邮箱列表与整改入口：同租户各行的「SES 状态」跟随租户资格，已开放显示启用，未开放、受限、复核中显示停用；原「状态」独立保留。租户管理员从受影响邮件页可在受限时提交整改，提交后原位置可查看进度；已开放或未开放时不显示整改入口。
平台 SES 状态：租户治理列表筛选「停用」同时包含未开通和受限/复核中的租户；详情以独立字段显示停用原因、整改进度。解除限制后列表与详情回到「启用」，不自动重发历史邮件。
受影响邮件：未发出显示无实际通道；管理员可按原因进入现有邮箱授权，客服只能看到处理建议。修复后仍是未发出，原工单手动提交后移除该待处理项。明确失败走原工单重试；结果未知先查询，拒收不能重试。
