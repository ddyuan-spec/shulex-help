### 流程与数据

1. 详情发起：#100 为目标，粘贴 #101、#102 按号查找并勾选；去除重复号，不能选自己。列表发起：先选多张源单，再选一个目标。候选显示主题、编号、状态、渠道/售后邮箱与获准查看的客户/订单信息。
2. 确认：目标与源分组显示；能返回修改和取消。确认后逐张复检权限与状态。结果分别展示成功和失败，提供查看目标、重试失败项；无权项不给摘要。超时显示结果待核对，不能再次提交已成功项。
3. 合后：#100「待处理」、#101「处理中」、#102「已解决」原样保留。源退出默认待办，仍可按编号打开；显示目标跳转并移除独立回复。目标显示带来源的消息与附件和双边操作记录。直接回复用目标线程；点源消息回复使用原线程，提交时校验发信权限并模拟拦截。旧线程回流可从评审外壳切换预置样例；原型不收发实际邮件。
4. 边界：同邮箱不同问题只做候选，不自动选中；AI处理中不可直接提交；重复提交或失败重试不重复创建关系；未找到、空输入、权限变化、部分失败均有独立可查看的反馈。

### 制作后验收基线

| 项 | 通过标准 |
| --- | --- |
| 布局 | 工作台与基底对比，无非需求布局改动；新增操作页留在工单工作区。 |
| 视觉 | 四种状态与选定基底一致，合单关系独立展示。 |
| 风格 | 无通用渐变卡片、说明墙或自行新增装饰。 |
| 文案 | 只用既有四态；操作结果、拒绝原因和原线程身份清楚。 |
| 导航 | NAV-MAP 所有入口、返回、取消与源单跳转可达。 |
| 状态 | 选择、确认、成功、部分失败、空态、禁止提交与已合入分别可复现。 |
| 交互 | 详情和列表两入口可走通；刷新保留模拟关系；失败重试不重复；回复路由可验证。 |
| 完整性 | 无死链或未定义引用；跑后台冒烟脚本及真实浏览器点击，记录未覆盖范围。 |
